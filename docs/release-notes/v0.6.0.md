# fretwire 0.6.0

**Favorites, a backup that holds everything, and a pedal that follows the editor both ways.**
Favorites now show up in the block picker and as a star on the chain, and they go into a device
backup along with user defaults. The backup itself got a round of fixes from an HX Stomp XL
owner's testing: it no longer drops records, walks empty slots, or flashes the pedal's
"Transferring data…" screen. Selecting a block in the GUI now moves the pedal's cursor, and
turning the pedal's encoder moves the GUI's selection.

32 commits since [`v0.5.1`](https://github.com/john-baxter-dev/fretwire/releases/tag/v0.5.1).

---

## Favorites

The pedal's favorites are read at connect. They appear as their own category in the block
picker, adding one places the block and cab with the favorite's values, and a block that matches
a favorite is drawn with a star. User defaults need nothing from fretwire, since the pedal
applies them itself when a block is added. On the CLI: `fretwire favorites` and
`fretwire add-favorite`.

`show-backup` lists the favorites in an HX Edit `.hxb`. With `--sections` it prints the file's
section table, and it now always names any tag it doesn't recognise instead of silently skipping
it.

## Device backup, format v4

- **Favorites and user defaults are backed up.** Both have checkboxes in the GUI and flags on
  the CLI. A restore reports them as held in the file but doesn't write them back yet.
- **HX Edit's order, presets last.** Settings, IRs, favorites and user defaults run first, so a
  backup you cancel partway through the preset sweep already has the rest (#18).
- **Unpopulated slots are left out,** as HX Edit leaves them out. The sweep used to load each
  empty slot to read it, which read back a document the firmware generates on the fly. On one
  tester's pedal that meant 81 identical copies and 22 s of a 25 s backup, and a restore then
  wrote all 81 into flash (#5).
- **Replies that span frames are reassembled.** Favorite listings, favorite records and the IR
  directory used to be read from their first frame only. That made a tester's 21 favorites back
  up as an empty list. A separate decoding bug skipped four records of exactly 138 bytes. Both
  are fixed, and a record that still can't be read is retried and then counted in the summary,
  so a gap is never silent (#5).
- **No more "Transferring data…" flash.** Reading favorite records inside a transfer session
  put up the pedal's banner. They are now read outside it, as HX Edit reads them (#22).
- A preset that reassembles but fails to parse is retried instead of aborting the backup.
- The GUI's backup dialog now sends the user-defaults flag under the name Tauri expects. A new
  check compares every frontend call against the Rust signatures.
- **HX Stomp XL** backups are recognised: its `.hxb` device ID came from an owner's file, so
  `show-backup` and `hxb-convert` accept it.

## Selection follows both ways

Clicking a block in the GUI now moves the pedal's cursor, so the pedal's panel shows the same
block (#21). Turning the encoder on the pedal moves the GUI's selection in turn. The pedal's
parameter *page* can't be followed: the device neither reports it nor lets it be set.

## Also

- **Tempo-synced blocks open again.** A block with a tempo-sync group would highlight when
  clicked but never open its parameter panel, because of a script error introduced in 0.5.1.
- **The preset panel fills the window** instead of stopping at 70% of its height (#20).
- **The routing grid always shows every column,** so a new preset has room to place blocks.
- **Toasts and uncaught GUI errors go to the backend log,** so a bug report doesn't have to be a
  screenshot.
- **Log colours only on a terminal.** `NO_COLOR` is honoured, and the CLI has
  `--color auto|always|never` (#19).
- **The README is accurate about the reference data.** Every live command needs it; only
  `detect`, `tree`, `decode-edit`, `show-backup` and `backup-show` run without it.

## POD Go: in progress

Work on issue #15 continues at the tester's pace. So far this release has:

- Load pricing for the models keyed by device suffix (this also prices the HX DL4 delays).
- No synthetic Amp+Cab category, which the POD Go doesn't have and refuses to swap into.
- Controller assignment sends POD Go Edit's own message body, which the pedal accepts where it
  refused the HX one. The source list now matches POD Go Edit's: None, FS1–FS8, EXP1/2 and
  Snapshots.

Controller assignment on a POD Go has not yet been confirmed on hardware.

## Known limits

- **Serve mode has no TLS of its own**; put it behind a tunnel or a proxy beyond a trusted LAN.
- **Favorites and user defaults are backed up but not restored.**
- **POD Go:** the IR directory is scanned rather than decoded.
- **Grid and routing planning is still DSP-0 only**; the settings namespace is mapped in part;
  IR reorder is delete-and-re-upload.
- **No firmware, flash or DFU traffic**, by design and permanently. See
  [`docs/safety.md`](https://github.com/john-baxter-dev/fretwire/blob/v0.6.0/docs/safety.md).

## Installing

Grab the `.deb`, `.rpm`, `.AppImage` or the Arch `.pkg.tar.zst` for the GUI, or the static
tarballs that run on any distro, x86-64 or arm64: **`fretwire-cli-*`** (the CLI),
**`fretwire-serve-*`** (the daemon, one file with the editor inside) and **`fretwire-mcp-*`**
(the MCP server). The deb, rpm and Arch package install the udev rule and the CLI alongside the
app; for the AppImage or the tarballs, install `packaging/70-hxstomp.rules` yourself and replug
the pedal.

On first run the app imports the model and preset reference data **from your own HX Edit
installation** (POD Go owners: from POD Go Edit). Nothing proprietary is shipped in these
packages, and nothing is sent anywhere unless you say yes to the update check.
