# fretwire 0.6.2

**Dual cabs, a backup that holds the pedal's banner to the end, IR dialogs you can click, and
the POD Go Wireless.** Owners of an HX Stomp XL and an HX Stomp reported the GUI and backup bugs
fixed here. A POD Go Wireless owner verified their pedal and sent the patch for it.

9 commits since [`v0.6.1`](https://github.com/john-baxter-dev/fretwire/releases/tag/v0.6.1).

---

## IR manager: Upload, Rename and Delete work from the GUI

Their dialogs opened *behind* the IR panel, and the first click landed on the panel's backdrop
and closed both, so none of the three could be used from the GUI (#32). Dialogs now always
stack above panels, and a test fails if they ever fall below again.

## Dual cabs

- **Add a dual cab, and change either cab on one** (#31). Before, you could edit a dual cab's
  mics but not add one or change its cabs. The picker has a new **Cab (Dual)** list, and on a
  dual block both **Change model** and **Change cab** open it.
- **The HX Stomp runs at most two Mic+IR cabs per preset.** A dual counts as two, so a third
  is refused, even when the DSP meter shows room. When that is why the pedal refused an add, the
  error now says so instead of reporting it as out of DSP.

## Device backup

- **"Transferring data…" stays up until the backup is done** (#30). Before, the pedal's banner
  cleared several seconds before the backup finished, which looks like it's safe to unplug. The
  backup now runs in one transfer session from the IRs to the last preset, as HX Edit's does.
- **Ctrl-C during `backup-device` releases the pedal.** The first Ctrl-C stops after the current
  read and closes the session cleanly, without writing a file. A second one quits immediately
  and warns that the pedal will need a power cycle. Before, Ctrl-C left the pedal on
  "Transferring data…" until you power-cycled it.
- **No banner flash before the backup starts.** The IR list is now read without opening a
  transfer session of its own.

## Input block: Gtr Pad

On an HX Stomp or Stomp XL, the input block shows **Gtr Pad** (Global / Off / On) under the gate
controls while the source is Main, and changing it writes to the pedal (#28). It's a setting
stored in the preset, not a block parameter, which is why it wasn't there before. **In-Z** and
**choosing the input source** (Main / Return / USB 5/6) are not supported yet: we haven't
found out how the pedal sets either one.

## POD Go Wireless: verified

The POD Go Wireless has its own USB id (`0x424b`) but identifies as a POD Go (`P34`), so it uses
POD Go Edit's reference data and the POD Go's edit commands (#29). On the owner's unit (fw 1.21
and 2.50), reads, the IR scan and a full device backup worked. A parameter change, a bypass
and a model swap each read back exactly, and a revert restored the preset byte-for-byte. Its
`.pgb` backups are recognised (device id `0x00210008`).

**Safety:** while POD Go Edit updates its firmware, a POD Go Wireless stays on its normal USB
id for about six minutes. fretwire now ignores any device that is in the middle of a firmware
update and never opens it. See
[`docs/safety.md`](https://github.com/john-baxter-dev/fretwire/blob/v0.6.2/docs/safety.md).

## Helix LT

An LT owner's backup and HX Edit captures (fw 3.80) added two more decoded commands: one that
routes an input or output (op 42) and one that removes a split (op 46). fretwire can build
both, but nothing uses them yet. They also gave the LT's backup device id (`0x00210004`) and
its four presets per bank. The LT stays at **reads verified, edits untested**. See
[`docs/helix-lt.md`](https://github.com/john-baxter-dev/fretwire/blob/v0.6.2/docs/helix-lt.md).

## Known limits

- **In-Z and the input source** can't be changed yet. The current source can be read.
- **Serve mode has no TLS of its own**; put it behind a tunnel or a proxy beyond a trusted LAN.
- **Favorites and user defaults are backed up but not restored.**
- **Assigning a block to a switch that already has one** is assumed to replace it, not add to it.
  This has not been captured.
- **Only some global settings have been identified**; IR reorder is delete-and-re-upload.
- **No firmware, flash or DFU traffic**, by design and permanently. See
  [`docs/safety.md`](https://github.com/john-baxter-dev/fretwire/blob/v0.6.2/docs/safety.md).

## Installing

Grab the `.deb`, `.rpm`, `.AppImage` or the Arch `.pkg.tar.zst` for the GUI, or the static
tarballs that run on any distro, x86-64 or arm64: **`fretwire-cli-*`** (the CLI),
**`fretwire-serve-*`** (the daemon, one file with the editor inside) and **`fretwire-mcp-*`**
(the MCP server). The deb, rpm and Arch package install the udev rule and the CLI alongside the
app. For the AppImage or the tarballs, install `packaging/70-hxstomp.rules` yourself and replug
the pedal. **The rule has a new line for the POD Go Wireless (`0x424b`)**, so owners of one
need to reinstall it. Nothing changed for other devices.

On first run the app imports the model and preset reference data **from your own HX Edit
installation** (POD Go owners: from POD Go Edit). Nothing proprietary is shipped in these
packages, and nothing is sent anywhere unless you say yes to the update check.
