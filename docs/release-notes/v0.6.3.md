# fretwire 0.6.3

**Restore goes where the dialog says, In-Z and the input source on the input block, and path B
drawn the way the Helix draws it.** A Helix Floor owner found the restore bug. An HX Stomp XL
owner asked for the input settings, and a Helix LT owner reported the path B drawing and sent
the slider layout.

5 commits since [`v0.6.2`](https://github.com/john-baxter-dev/fretwire/releases/tag/v0.6.2).

---

## Restore writes into the setlist the dialog shows

On a device with several setlists, Restore could write into a different setlist from the one
the dialog listed (#33). Restoring a single-preset file while browsing USER 5 put it in the
same slot of FACTORY 1, because the file's own setlist chose the destination. Restore now
writes into the setlist whose slots the dialog shows, and the status line names it.

Restoring into a setlist other than the loaded preset's now follows the same rule as Save As.
fretwire refuses it unless `FRETWIRE_SETLISTS=1` is set, because writing across setlists has
never been run against a Helix Floor.

**If you restored on a Helix Floor, LT, Rack or another multi-setlist device with an earlier version, check
that the presets landed where you expected.**

## Input block: In-Z and the input source

On an HX Stomp or Stomp XL, the input block now has a **Source** dropdown (Main L/R, Return L/R,
USB 5/6) and **In-Z** beside Gtr Pad (#28). In-Z and Gtr Pad show only while the source is Main.
Leaving Main resets In-Z to Auto on the pedal too. Both were confirmed on an HX Stomp (fw 3.71).
The XL is assumed to use the same values, and its owner reports the same three sources.

The CLI has `input-source [value]`, and the MCP server's `param_set` reaches the source, In-Z
and Gtr Pad.

## Path B drawn the way the Helix draws it

When the split and join sit closer together than the blocks on path B, fretwire marked the
outer B blocks "outside path B" (#34). A Line 6 factory preset (GlitchVerb on the LT) laid out
that way plays all of them on path B, so the badge was wrong and is gone. Path B is now drawn
as the pedal's own screen draws it. The split drops to a rail that runs past the outermost B
blocks, through every one of them in column order, and back to the mixer.

## Longer sliders

Parameter sliders are stacked in one column, so they're longer and finer to drag (#35). A block
with parameter groups, such as an amp+cab, gets one column per group. A parameter linked to the
snapshot controller is labelled "Snap".

## Known limits

- **`.hlx` files can't be restored directly yet.** Convert them with `fretwire hxb-convert`
  first. Direct import for the HX Stomp is in review (#36).
- **Serve mode has no TLS of its own**; put it behind a tunnel or a proxy beyond a trusted LAN.
- **Favorites and user defaults are backed up but not restored.**
- **Assigning a block to a switch that already has one** is assumed to replace it, not add to it.
  This has not been captured.
- **Only some global settings have been identified**; IR reorder is delete-and-re-upload.
- **No firmware, flash or DFU traffic**, by design and permanently. See
  [`docs/safety.md`](https://github.com/john-baxter-dev/fretwire/blob/v0.6.3/docs/safety.md).

## Installing

Grab the `.deb`, `.rpm`, `.AppImage` or the Arch `.pkg.tar.zst` for the GUI, or the static
tarballs that run on any distro, x86-64 or arm64: **`fretwire-cli-*`** (the CLI),
**`fretwire-serve-*`** (the daemon, one file with the editor inside) and **`fretwire-mcp-*`**
(the MCP server). The deb, rpm and Arch package install the udev rule and the CLI alongside the
app. For the AppImage or the tarballs, install `packaging/70-hxstomp.rules` yourself and replug
the pedal. The rule is unchanged since 0.6.2.

On first run the app imports the model and preset reference data **from your own HX Edit
installation** (POD Go owners: from POD Go Edit). Nothing proprietary is shipped in these
packages, and nothing is sent anywhere unless you say yes to the update check.
